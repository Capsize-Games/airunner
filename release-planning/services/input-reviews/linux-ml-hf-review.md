## Private source copies and static artifact checks

All 18 upstream release tags were copied with reachable history into independent private repositories under `Capsize-Games/<project>-maintenance`. The repositories were verified private, not forks, with GitHub Actions disabled before source history was pushed; no automatic upstream sync is configured. Each `source-review/<tag>` branch points to the exact source commit listed above. License and copyright files were preserved.

Every selected wheel RECORD reconciles for paths, sizes, and hashes. Static archive scans found no unsafe paths, symlinks, hardlinks, special archive entries, duplicate wheel paths, or `.pth` files in the selected wheels or available sdists. The reviewed Tokenizers candidate wheel includes its upstream project `LICENSE` and the exact locked Rust-crate notice bundle. The selected bitsandbytes wheel includes `LICENSE` and `NOTICE.md`; PyArrow includes `LICENSE.txt` and `NOTICE.txt`; sentence-transformers includes `LICENSE` and `NOTICE.txt`; multiprocess includes `COPYING` and `LICENSE`.

Native files are present in the selected upstream wheels for bitsandbytes (11), hf-xet (1), PyArrow (24), safetensors (1), and Tokenizers (1). Tokenizers’ native file was replaced with the locally built patched extension; its ELF dependencies and ABI symbols were inspected, and the exact wheel was imported in an isolated CPython 3.13.5 environment. This bounded review does not establish source-to-binary reproducibility or complete source-code semantic audit. The source declares native build paths for Rust/PyO3, C++/Arrow, and CUDA components. No source build was run for the other packages. The intended install path uses wheels with `--only-binary=:all:`; Python packaging backend dependencies were not run or reviewed as build inputs for Tokenizers because wheel assembly was offline and static.

Three source snapshots contain agent guidance. The hf-xet `AGENTS.md` describes Rust build/test workflow; markdown-it-py `AGENTS.md` describes project structure and tox commands; Typer `.agents/skills/typer/SKILL.md` provides API conventions and examples. These files were read as untrusted package data. They do not request credentials or system changes. No instructions were followed or executed.

Static source searches found expected package behavior: Hub clients and hf-xet download/upload model and dataset content and support caller-provided authentication; datasets reads caller-selected sources; bitsandbytes loads its CUDA/native backend; dill and multiprocess provide serialization/process APIs; Transformers supports remote model code when explicitly enabled. These findings describe package features, not automatic telemetry. No package import, authentication, network call, deserialization, model code, or dataset operation was run.

## Advisory findings and exact replacement review

PyPI release vulnerability records and OSV exact-version results were captured on 2026-11-02. Fifteen original candidate pins had no advisory records in that snapshot. Three pins are affected:

- **Accelerate 1.14.0** (`GHSA-4j2p-28q2-5m79`, `PYSEC-2026-3804`): untrusted shard filenames in an index can escape the checkpoint directory; FIFO targets can block checkpoint loading. Static inspection also found the same missing path containment in the latest public 1.15.0 source. OSV provides no fixed release floor.
- **Datasets 4.0.0** (`GHSA-379c-qx7v-6h59`, `PYSEC-2026-3716`): folder-based builders did not validate metadata `file_name` paths before reading them. Fixed in 5.0.1.
- **Transformers 5.8.1** (`GHSA-x9r9-c232-4q39`, `GHSA-xrqw-3rrv-vx5w` and PYSEC aliases): a custom generation module could be cached before remote-code consent, and chat-template names could write outside the save directory. Static source review found both fixes in 5.22.0. The consent-order vulnerability still existed in inspected 5.10.0 source even though OSV listed 5.8.1 as last affected.
