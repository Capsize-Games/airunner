# Linux audio/TTS/STT source review

## Scope

This review covers the 20 exact audio-related pins in the Linux CPython 3.13 candidate lock dated 2026-11-02. For each pin, the exact PyPI source distribution and selected Linux-compatible wheel were fetched from the version-specific PyPI release record. Each artifact SHA-256 matches PyPI metadata and a hash listed for that version in the candidate lock. The source distributions and wheels are preserved in an owner-controlled private archive with release metadata. The candidate lock remains unactivated.

The review read each source archive as data, checked project build metadata and package-defined build commands, searched source/build files for network, process, credential, telemetry and agent-instruction paths, and inspected each wheel’s metadata, license files and `RECORD`. Native wheel payloads were inspected as ELF files without loading them. Exact package versions were queried against OSV on 2026-11-02; no matching advisories were returned. GitHub’s advisory list for pyttsx3 was also empty.

## Findings

- The wheels’ `RECORD` hashes and sizes validated. Native extensions in the selected wheels are `audioop-lts`, `llvmlite`, `msgpack`, `numba`, `soundfile`, and `soxr`. Their ELF dependencies are system runtime libraries; `numba` also ships optional threading backends with OpenMP/TBB dependencies. No extension was loaded.
- The `llvmlite` wheel carries LLVM license notices; the `numba` wheel carries third-party notices. `soundfile` bundles libsndfile and its LGPL text. `soxr` carries LGPL and PFFFT notices. Pycountry’s LGPL license and data copyright file are present. The standard-library backport wheels retain PSF notices.
- `audioread` launches selected local decoder programs with argument lists. `pooch` implements caller-directed HTTP/FTP/SFTP downloads for requested data; source inspection found no automatic download or telemetry path. No credential store is accessed by the reviewed runtime paths.
- Build metadata uses setuptools, Poetry, Flit, scikit-build-core, or legacy `setup.py` backends. `llvmlite` and `numba` define native build commands; `soxr` builds its bundled resampler source. These build hooks were inspected as data and not run for these packages. The selected wheels are binary artifacts, so their source build hooks are not run at installation.
- The upstream `pyttsx3==2.91` artifact is quarantined from candidate use while its maintainer is contacted through a nontechnical [request for a preferred private contact](https://github.com/nateshmbhat/pyttsx3/issues/452) is pending. A local patched candidate has separate private source and wheel provenance. The public record omits technical details while coordinated reporting is pending. Its MPL-2.0 notice is preserved.
- The `pyttsx3` wheel does not include eSpeak NG. The Python driver loads an OS-provided eSpeak library; that native system dependency is outside these 20 PyPI artifacts and their pip hashes. The mirrored upstream eSpeak NG `1.52.0` tag resolves to commit `4870adfa25b1a32b4361592f1be8a40337c58d6c`; its source states GPL version 3 and includes separate Apache-2.0, BSD-2-Clause, and Unicode notices. This was a bounded source identity, license, and build-configuration check, not a complete security review of the full C codebase or a review of the deployed OS package. The exact OS package revision/source hash and its installed `espeak-ng`/`libespeak-ng` files are not recorded in the pip candidate evidence.
- The eSpeak NG CMake configuration can fetch Sonic from Git when a system Sonic library is absent; it pins commit `fbf75c3d6d846bad3bb3d456cbc5d07d9fd8c104` but does not pin an archive digest. Do not use this direct CMake build path without separately verified Sonic source or a reviewed system library. This does not establish whether the deployed distribution package exercised that path.
- The private patched `pyttsx3` candidate is `2.91+capsize.1`, derived from the exact upstream tag and separately preserved patch commit. Its 17-entry wheel `RECORD` validates, and the embedded MPL-2.0 license hash matches its private build manifest. It was built offline using the hashed build-tool inputs recorded privately. The artifact remains private and is not activated. The current public dependency workflow has no configured authenticated input for it; adding a secret fetch would still place the patched package in a public release artifact, so it cannot preserve confidentiality there while coordinated security handling is pending.

## Limits and exclusions

No target package was installed or imported. The only executed checks were four isolated tests of the local pyttsx3 command helper with `subprocess.run` mocked; no audio command, audio device, model or TTS runtime ran. The local pyttsx3 candidate wheel was built from its patched source using the existing hashed build-tool environment with uv offline/no index; other package wheels were fetched, not rebuilt. No native dependency was compiled. No model, speech sample or GPU workload was downloaded or run. These checks do not establish runtime playback, inference, performance, or OS-package provenance for eSpeak NG.

The source review is limited to the exact artifacts, build metadata, wheel payloads and versions listed above. It does not review every upstream history commit, every optional backend, or the platform-specific wheels for Windows/macOS. The 20 pins are evidence for a candidate only; no active lock or release-input manifest was changed here.
